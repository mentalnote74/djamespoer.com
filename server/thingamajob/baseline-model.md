# TEST baseline LoT and exception review

`baseline.sql` is additive. It introduces immutable source-vetting evaluations,
exception definitions, owner answers and operator policy-job provenance. It does
not manufacture owner reviews or rewrite the original extracted proposals.

For this proof the authorized job is generated by
`scripts/thingamajob-baseline-backfill.mjs`. It accepts only the pinned original
65-candidate package, verifies the complete remote run against it, matches the
registered source hashes to the private source projections, and checks literal
citations. The bounded source-vetting policy considers the original source
language, questions, conflicts and qualifications. Model confidence and citation
substring matching alone are not a general entailment proof; arbitrary future
model output cannot reuse this job approval. No benchmark input is read.

The generated SQL is private under `career-source/baseline-vetting/`; apply it
only to the configured TEST D1 after applying the additive schema. It records
explicit rollout authorization, policy version, run fingerprint, evidence digest,
classification/reasons and timestamps. Commit-time guards verify the immutable
run, active source-owning workspace and registered originals. Reapplication is
idempotent. The generated job is not a browser-supplied trust grant.

`thingamajob_active_baseline` is actual active LoT selection for automatic facts.
Only baseline-classified, still-unreviewed original proposals appear there.
`workflowSnapshot.baselineClaims` exposes those facts only within the authorized
owner workspace, alongside the existing manually reviewed active claims. No
fictional accepted review is added. Qualified/informational entries remain
inspectable with caveats but are not active truth or blocking questions.

An explicit later correction/rejection of an automatic baseline uses its original
proposal and the existing owner-review service. The baseline view immediately
excludes it. Accept/Correct creates the normal reviewed replacement; Reject
removes it from active truth. The immutable evaluation, original extraction,
review and source lineage remain linked by the same proposal/run/candidate IDs.
The existing subsequent supersession model continues to govern reviewed claims.

The four extraction questions remain unchanged. An additional elapsed-time
inference produces a fifth exception. The UI presents one focused question with
its two or three related statements and citations, and one explicit save action.
Owner context is stored separately from source evidence. Unchanged statements
are explicitly accepted, edited ones corrected and checked statements rejected
through the existing review API. No answer or decision is automatic. Each review
is atomic; an interrupted group retains its valid partial history and can resume
without duplicates. The question is marked answered only after its decisions
succeed. Changed/concurrent decisions fail closed, never silently overwritten.

Both read and resolution endpoints use the existing verified human identity,
owner/workspace authorization and same-origin mutation protection. Request actor,
role and workspace fields grant no authority. LIVE has no extraction-run route.
No R2 object is modified by the baseline job.

## Source-specific title presentations

Title wording alone is not a contradiction or evidence of promotion. Canonical
employer titles, source-presented titles and substantive employment conflicts
are distinct. Association requires employer context, compatible date precision
and corroborating responsibilities/technology; explicit separate roles or
material responsibility/seniority evidence still require judgment.

`title-presentations.sql` appends immutable evaluation/issue reassessments and
source-specific role presentations. Current views select the latest assessment.
Original candidate text, original flags/questions, citations and any owner
answers remain untouched. Informational title questions cannot be submitted as
current conflicts. They remain available under title presentation history.
Canonical titles stay unset unless separately established; this policy does not
promote a source headline into a canonical employer fact.

The pinned TEST reassessment tool is
`scripts/thingamajob-title-reassessment.mjs`. It verifies the exact approved run
and source hashes, records rollout authorization, and appends four title
presentations and two nonblocking question assessments. It makes no model calls.
The original extraction instructions are corrected for future calls; the
accepted extraction package is not regenerated or edited.
